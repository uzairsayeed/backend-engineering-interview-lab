Node.js vs FastAPI — Request Flow
========================================================================


NODE.JS                          FASTAPI (this project)
─────────────────────────────    ──────────────────────────────────────
server.js                        uvicorn  (external process, not your code)
    ↓                                ↓
app.js                           main.py  (creates app, mounts router, registers handlers)
    ↓                                ↓
router.js                        routers/urls.py  (APIRouter with prefix="/urls")
    ↓                                ↓
middleware.js                    FastAPI internals  (JSON parsing, validation, DI resolution)
    ↓                                ↓
route.js + controller.js         routers/urls.py → create_short_url()  (these are merged in FastAPI)
    ↓                                ↓
service.js                       service.py → ShortUrlService.create_url()
    ↓                                ↓
repository.js                    repository.py → ShortUrlRepository.save()

--------------------------------------------------------------------------------------------------------
Detailed flow for POST /urls
========================================================================

1. uvicorn
   Receives the raw TCP request and hands it to FastAPI

2. main.py
   FastAPI matches the path/method → finds create_short_url() in urls.router

3. FastAPI internals (automatic)
   ├── Parses JSON body → validates against CreateShortUrlRequest (schemas.py)
   ├── Resolves Depends(get_short_url_service) → returns the singleton _service (dependencies.py)
   └── Injects: payload, request, response, service into the route function

4. routers/urls.py → create_short_url()
   ├── Calls service.create_url(destination_url, custom_code, expires_in_seconds)
   ├── Sets response.headers["Location"]
   └── Calls to_short_url_response() → maps ShortUrl model → ShortUrlResponse (mappers.py)

5. service.py → ShortUrlService.create_url()
   ├── Generates/validates short code
   ├── Builds ShortUrl model (models.py)
   └── Calls repository.save(short_url)

6. repository.py → ShortUrlRepository.save()
   └── Stores in _urls dict, returns ShortUrl

7. Back up the chain
   service returns ShortUrl → route returns ShortUrlResponse → FastAPI serializes to JSON → uvicorn sends HTTP 201

The key differences from Node.js
========================================================================

------------------------------------------------------------------------------
Node.js	                                 |      FastAPI
------------------------------------------------------------------------------
server.js is your code                   | uvicorn is external — not your code
Route + Controller are separate files    | Merged — the route function IS the controller
Middleware is explicit in the chain      | FastAPI handles parsing/validation/DI automatically before your function runs
Error middleware at the bottom of app.js | exception_handlers.py registered once in main.py
------------------------------------------------------------------------------

The biggest conceptual shift is that FastAPI collapses the middleware + controller step into the route function itself — by the time your create_short_url() runs, 
the request is already parsed, validated, and dependencies injected.

Categories of failures
========================================================================

Expected domain failure
    Duplicate code, missing URL, expired URL
    → Specific 4xx or 503 response

Invalid HTTP request
    Invalid URL, malformed path, missing field
    → 422 response

Unexpected application error
    Programming bug, unavailable dependency, unknown failure
    → Generic 500 response
